`sk-cron-run`, the scheduled-job observability wrapper, now ships from skcapstone as an installed command at `~/.skenv/bin/sk-cron-run` (a `script-files` entry beside `sk-alert`) instead of existing only as a loose script in the skos checkout that 31 systemd drop-ins named by absolute path. The units that most need wrapping are the repo-shipped skfleet seats, which run on fleet nodes where skos is not installed, so a skos-only runner could never wrap them and an `ExecStart` naming an absent binary fails the unit at activation. A node without skos now gets the run-ledger record and the realtime alert as normal, and the GTD capture reports itself as skipped rather than failed.
