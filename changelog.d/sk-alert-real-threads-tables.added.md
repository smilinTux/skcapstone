`sk-alert` opens a real Talk thread per alert condition and can keep a queryable row per condition in Nextcloud Tables. The first alert for a key is posted with a `threadTitle` (the old `replyTo` grouping only quoted the root and left everything in the main timeline, so there was no thread at all) and later ones go in with `threadId`. Because alerts are posted as the estate's agent account, the thread is the agent's own, so a person replying inside it reaches Lumina (nor) or Jarvis (chi) even in a mention-only room. New flags: `--thread KEY` groups without de-dup (for callers like sk-cron-run that own their repeat policy), `--title`, `--resolve` (posts the last word into the thread, puts a check mark on its title, forgets the root, clears the de-dup stamp and marks the row resolved) and `--table-only` (backfill). With `SKALERT_TABLE_ID` set, every alert upserts a row in that table (columns found by title); `sk-alert-table-setup` creates the table once per estate. A Tables failure is logged and never fails the alert.
