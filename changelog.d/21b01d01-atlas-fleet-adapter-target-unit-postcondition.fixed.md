ATLAS fleet honor path (card 21b01d01): a fleet `restart_service` now restarts only the `.service` unit named by the object's SIGNED fleet spec (`spec.unit`, verified with converge's `verify_desired` and allowed by the node profile via `profiles.unit_allowed`), never the object name or a unit the proposal supplies, and only when the object is placed on this node. Anything else (another node, no placement, no or non-service unit, unsigned spec or placement, outside the profile, a docker, paused or deleted service, a fleet action with no physical muscle, a rollback naming another object or unit) is refused before anything runs: `fleet_target_known` refuses it in preflight so the approved change is not spent, and in either lane it never feeds the circuit breaker or runs a rollback. The postcondition after a fleet restart waits up to 75 s (capped at 120 s and by the pass deadline) for the node to re-observe the unit and accepts only evidence written strictly after the restart. Fleet conditions now carry the time their node wrote the status file they come from, not the pass clock; a steadily failed service therefore reads as stale and is refused (documented limitation).
