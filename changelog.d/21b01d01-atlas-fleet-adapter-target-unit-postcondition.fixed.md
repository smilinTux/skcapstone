ATLAS fleet honor path (card 21b01d01): a fleet `restart_service` now restarts the unit named by the object's fleet spec (`spec.unit`), never the object name or a unit the proposal supplies, and only when the object is placed on this node. Anything else (another node, no placement, no unit mapping, a docker or paused service, a fleet action with no physical muscle) is refused before anything runs, opens no ITIL change, and escalates without feeding the circuit breaker. The postcondition after a fleet restart waits up to 75 s (capped at 120 s) for the node to re-observe the unit and accepts only evidence written at or after the restart, so a real restart can verify and the pre-action status never does. Fleet conditions now carry the time their node wrote the status file they come from, not the pass clock.
