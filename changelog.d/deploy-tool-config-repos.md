- `skcapstone deploy` takes a per-cluster config repo for a tool: `nodes.<node>.configs.<tool>` (repo or url, a ref on main, the instance directory). It is exported next to the tool as `<tool>-config`, and the units in `<instance>/systemd/` are rendered (`@TOOL@`, `@CONFIG@`) and installed as the whole unit, with that unit's hand drop-ins moved aside. Refused before publishing when a unit names a file the exports lack; undone on a failed smoke; drift reports a config export off its ref. See docs/DEPLOY.md, "Per-cluster config repos".
