`sk-alert`, the estate's alert primitive, now ships with skcapstone instead of living in `~/.hermes/scripts/lib/skalert.sh` behind a hand-made symlink. skcapstone's own ops scripts (`skcapstone-gfs-backup.sh`, `sync-conflict-guard.sh`, `skfleet-auto-rollout.sh`) are its biggest callers and each guards with `[ -x "$bin/sk-alert" ]`, so on a node without Hermes every alert was a silent no-op: on 2026-10-30 all four chi nodes had skcapstone, none had sk-alert, and the live conflict-guard timer there had been reporting Syncthing conflicts to nobody. Routing now comes from `config/alert.env` (estate-wide, Syncthing-shared) with secrets in node-local `config/alert.secret`, no recipient or room is hardcoded, and delivery succeeds when any configured channel accepts the message so an estate with only Nextcloud Talk and no Telegram token still alerts.
