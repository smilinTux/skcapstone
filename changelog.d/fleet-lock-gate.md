`deploy/fleet-constraints.txt` is now the fleet runtime's fully resolved lock (every package and
transitive dependency, universal markers for Python 3.12 and 3.14), generated by
`scripts/fleet-lock.sh` from `deploy/fleet-requirements.in` (SK pins), `deploy/fleet-tools.in`
(third-party tools in the same venv) and `deploy/fleet-self.in`. The rollout pins every lock
entry a host has installed and runs `pip check` right after the parity gate, so a conflicting
set halts on the canary. `.github/workflows/fleet-lock.yml` gates every lock PR: lock current,
fresh-venv install on 3.12 and 3.14, `pip check`, parity, import and `--help` smoke of every SK
package and MCP server, upper caps only from `deploy/dependency-caps.md`, no lowered security
package without a `security-downgrade:` line, and pip-audit (PyPI and OSV). `skcapstone deploy
plan` resolves the node's pinned set; `resolve: strict` in a manifest makes plan and apply refuse
a set that does not resolve. skcapstone drops its rich, click, pydantic and pyyaml upper caps.
