# PR Policy Implementation Plan (nimble-factory Plan B1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Stop requiring a pull request for every worker change, so a routine card
costs two fast checks instead of a full PR cycle, while keeping provenance and
keeping a PR mandatory for sensitive work.

**Architecture:** The change is almost entirely in the worker launch prompt plus
one new decision helper. Nothing validates a PR URL in code today, so the policy
lives in the prompt and the evidence record, not in a contract that must migrate.

**Tech Stack:** Python 3.12, `scripts/fleet/skfleet-rotate.py` (a script, not
importable), pytest.

**Spec:** `docs/superpowers/specs/2026-09-16-nimble-factory-design.md` section 3.5.

## Measured facts this plan rests on

Verified 2026-09-17 against the tree and the live workflows, not assumed:

```
fires on ANY branch push    docs-check, secret-scan          about 0.4 min total
fires on PR or main only    ci, pytest, providers, publish
```

- Nothing in code requires or validates a PR URL. The requirement exists only as
  launch-prompt text at `skfleet-rotate.py:6203-6204`. Confirmed by grep across
  `scripts/fleet/` and `src/skcapstone/`: the only hits are those two prompt lines.
- The sensitive-category matcher already exists: `_SENSITIVE_CATEGORY` at
  `skfleet-rotate.py:1804`, matching
  `capauth|credential|custody|issuer|secret|\bkey\b|rollback|deploy|production|release|migrat`.
  **It is duplicated at line 5734.** Treat that as a known hazard, see Task 1.
- `_CATEGORY_OPT_IN = "dispatch-approved"` at line 1807 is the existing opt-in tag
  for those categories.

## Global Constraints

- Python 3.12.
- `scripts/fleet/` is outside black and ruff. `src/` and `tests/` are NOT: CI runs
  `black --check src/ tests/` and `ruff check src/`. Run both before committing.
- No em dashes or en dashes anywhere, including comments and commit messages.
- No `Co-Authored-By` trailer unless you can evidence the co-author.
- `skfleet-rotate.py` is a script with no import-time side effects. Tests exercise
  it by AST extraction, as the existing `tests/test_skfleet_*.py` files do.
- Commit as soon as a fast check passes. Never gate a commit on a long test run.
- When reverting your own change to prove a test catches it, print the mutated line
  back FROM DISK before running the suite.

### Task 2: Decide PR-now versus branch-push-only

**Files:**
- Modify: `scripts/fleet/skfleet-rotate.py`
- Test: `tests/test_skfleet_pr_policy.py`

**Interfaces:**
- Consumes: `_SENSITIVE_CATEGORY` from Task 1.
- Produces: `def pr_required(core) -> bool`, taking the raw `core.json` dict.

`pr_required` returns True when the card's title or any tag matches
`_SENSITIVE_CATEGORY`, and False otherwise. Read the card as raw JSON. Do NOT read
it through `CardCore` or `CardStore.fold`: Plan A established that the dispatcher
reads raw JSON throughout, and a model read silently drops fields on a node running
an older skcoord.

- [ ] **Step 1: Write failing tests.** A card titled "rotate the deploy key"
  requires a PR. A card titled "fix a typo in the README" does not. A card with tag
  `migration` requires one. A card with neither requires none. An empty or absent
  title must not raise.
- [ ] **Step 2: Run them, confirm they FAIL** with the function undefined.
- [ ] **Step 3: Implement `pr_required`** near `_SENSITIVE_CATEGORY`.
- [ ] **Step 4: Run the tests, confirm they pass.**
- [ ] **Step 5: Mutation-check.** Invert the return, print the mutated line back
  from disk to prove the edit landed, confirm the tests go red, restore.
- [ ] **Step 6: Commit.**

### Task 3: Rewrite the DEFINITION OF DONE in the worker launch prompt

**Files:**
- Modify: `scripts/fleet/skfleet-rotate.py` around lines 6130 and 6190-6210
- Test: `tests/test_skfleet_pr_policy.py`

This is the behavioural change. The current prompt says, verbatim, *"Work is NOT
done until it is an open pull request"* and *"Put the PR URL in your verdict"*.

New default, replacing steps 3 and 4 of DEFINITION OF DONE:

1. Branch first, never commit to main.
2. Commit as soon as a fast check passes.
3. **Push the branch.** The pushed branch plus the recorded SHA is the handoff.
4. **Put the exact commit SHA and the branch name in your verdict and your skmail.**
   A verdict claiming work was done with no reachable SHA is incomplete.
5. **Open a PR only when the card is sensitive** (the prompt must say which
   categories: capauth, credential, custody, issuer, secret, key, rollback, deploy,
   production, release, migration) **or when asked to.** Otherwise a PR is opened
   once per batch by the Integrator seat, not by you.

Keep unchanged: never commit or push to main, never merge, attribute the commit to
yourself, clean up worktrees, never use an em dash.

The prompt must state WHY, briefly, because a worker that does not understand the
rule reverts to the habit: an unpushed commit is destroyed by any other session's
checkout, so pushing is mandatory; a PR is what costs 20 to 30 minutes of CI and
wait, so it is reserved for changes that earn it.

- [ ] **Step 1: Write failing tests** asserting the assembled launch string
  contains the new SHA-based requirement and does NOT contain
  "Work is NOT done until it is an open pull request". Follow the existing
  launch-string tests in `tests/` for how the string is assembled.
- [ ] **Step 2: Run them, confirm they FAIL.**
- [ ] **Step 3: Rewrite the prompt block.** When `pr_required(core)` is True, the
  prompt must additionally instruct the worker to open a PR immediately and say why.
- [ ] **Step 4: Run the tests plus `pytest tests/ -k skfleet -q`.**
- [ ] **Step 5: Verify the script parses.**
- [ ] **Step 6: Commit.**

### Task 4: Record the branch and SHA as evidence

**Files:**
- Modify: `scripts/fleet/skfleet-rotate.py`
- Test: `tests/test_skfleet_pr_policy.py`

The spec's justification for dropping PR-per-change is that *"the branch push plus
the replicated evidence record"* provides the cross-host visibility a PR used to.
That only holds if the SHA is actually recorded.

**Enumerate the evidence-recording path yourself before you start.** Do not trust a
count or a path from this plan. In Plan A the controller's call-site counts were
wrong three times (7, then 8, then actually 10), and every resulting defect came
from acting on an assumed surface rather than a measured one. Find where worker
evidence is written today, report what you found, and record the branch and SHA
through that existing path rather than inventing a parallel store.

- [ ] **Step 1: Enumerate and report** the existing evidence path. Write what you
  found into your report before writing code.
- [ ] **Step 2: Write the failing test** asserting a completed worker records a
  branch name and a 40-character SHA retrievable through that path.
- [ ] **Step 3: Run it, confirm it FAILS.**
- [ ] **Step 4: Implement.**
- [ ] **Step 5: Run the tests.**
- [ ] **Step 6: Commit.**
