# Production dependency set of the fleet runtime: THE single source of truth.
#
# These are the versions installed in ~/.skenv on every chi host (chiap01-04,
# chiap08), verified 2026-10-13. Three consumers read this one file:
#   1. CI installs the package with `pip install -c deploy/fleet-constraints.txt`,
#      so tests run against what production runs, not against the pyproject floor.
#   2. Rollout installs with the same `-c`, so a host is moved to exactly these.
#   3. The rollout gate runs `src/skcapstone/fleet/dependency_parity.py`
#      and halts with DEPENDENCY_DRIFT if an installed version differs.
#
# Scope: only packages CI can install from the same index production used.
# skskills is deliberately NOT pinned: hosts run 0.2.0 built from git commit
# 14266f0 (direct_url.json), but the index CI uses only has 0.1.0/0.1.1, so a
# pin makes resolution impossible. Pin skskills here once 0.2.0 is published to
# the index.
#
# skwhisper is deliberately NOT pinned for the same reason: every chi host runs
# 0.6.2 built from the smilinTux/skwhisper repo (tag v0.6.2), but the index only
# carries 0.1.0, because that repo has no publish workflow at all. Pinning 0.6.2
# would make resolution impossible, and pinning 0.1.0 would DOWNGRADE every host.
# Add the pin once skwhisper publishes 0.6.2+ to the index.
#
# Rules: exact `==` pins only. A pyproject floor must never exceed its pin
# (tests/test_fleet_dependency_parity.py). To bump, see
# docs/fleet/DEPLOY-FROM-MAIN.md "Bumping a fleet dependency": the upstream
# release ships first, then the pin moves in the same PR as the code needing it.
skcoord==0.1.88
skmemory==0.11.67
cloud9==1.2.4
